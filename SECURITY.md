# Security policy

## Report a vulnerability privately

Use GitHub's private vulnerability reporting. On this repository's page, open the **Security** tab,
then choose **Report a vulnerability** and fill in the form. The report reaches the repository's
maintainers privately; it is not public.

Do not open a public issue, discussion or pull request for a vulnerability, and do not describe it in
a public place, until a fix has been released.

## What to include

A report helps most when it has:

- the version or commit you tested;
- the steps to reproduce it, as short as you can make them;
- what an attacker gains (the impact);
- your suggestion for a fix, if you have one.

Use synthetic data only. Do not include real customer, employer or personal data, or credentials, in
a report.

## What to expect

1. A maintainer reads your report.
2. If something is missing, the maintainer asks you for it in the same private conversation.
3. A fix is prepared in private.
4. The fix is released and a security advisory is published.
5. You are credited in the advisory if you wish.

This file makes no promise about how long each step takes.
